# Phase 0: results for the unknowns in spec section 14 (P0.6)

Environment: Obsidian 1.14.4 desktop on macOS (Apple silicon), isolated profile and scratch vault, driven over CDP. Run 2026-10-20. The spec's minimum version (1.13.7) could not be installed here, so results are **verified on 1.14.4 only**.

Legend: **Works** · **Works with a limit** · **Fails** · **Untested** (could not be tried on this machine).

| # | Unknown | Result | Evidence and consequence |
| --- | --- | --- | --- |
| U1 | A custom widget can be registered for schema-covered properties | **Works with a limit** | `app.metadataTypeManager.registeredTypeWidgets` exists (keys: aliases, checkbox, date, datetime, file, folder, multitext, property, number, tags, text). A widget registered there and returned from a wrapped `getTypeInfo(key, value)` rendered in the Properties panel. `render(el, data, ctx)` receives `ctx = { app, key, onChange, sourcePath, blur, hoverSource }`. **Limit:** `getTypeInfo` receives only `(key, value)`, no file, so the decision per note must be made inside `render` using `ctx.sourcePath`. Design D-09: return a decorated copy of the widget Obsidian already chose and decorate only when the note has a schema. |
| U2 | Option (Mac) can be detected while a property field has focus | **Works** | CDP `Input.dispatchKeyEvent` for Alt with the modifier bit: a capture-phase `keydown` on `document` saw `key: "Alt", altKey: true`, target = the focused property input; held key produced `repeat: true` events (start the timer only when `repeat` is false); `keyup` seen. Real physical keyboards were not used. |
| U3 | Alt on Windows does not move focus to a menu bar | **Untested** | No Windows machine. The setting "Hold key" allows another key (Shift, Control, Meta, or Alt). We call `preventDefault()` on the lone Alt keyup only when our list opened. Written into the Windows manual checklist (`testing.md`). |
| U4 | A hidden `.schema` folder can be read, watched and synced | **Works with a limit** | `vault.adapter.list/read/stat/write` work on `.schema/`. Obsidian fires **no** vault events for it (`getAbstractFileByPath('.schema/a.yaml')` is null). Visible `_schema/` fires `create`/`modify` events. Design: events for a visible folder; polling `adapter.stat` every 2 s for a hidden one, plus the manual "Reload schemas" command. Sync of hidden folders depends on the sync service and was **not tested**. |
| U5 | Bases treats `YYYY-MM-DDTHH:mm` as a date and time | **Works with a limit** | Obsidian's own type inference returns `datetime` for `2026-10-20T14:32` and `date` for `2026-10-20`. Bases sorting and filtering themselves were not exercised (no Bases view built); inference is the same machinery. Keep the format. |
| U6 | Obsidian's frontmatter editing keeps the order the plugin writes | **Works with a limit** | `processFrontMatter` preserves key order as assigned (delete all keys, re-add in order). **Limit, disagreement with spec rule 9:** on a CRLF file it wrote the frontmatter lines with LF while leaving the `---` delimiters and the body CRLF, producing mixed line endings. A no-op callback did not rewrite the file. Decision D-07: write frontmatter ourselves through `vault.process` and keep the file's EOL. |
| U7 | A plugin can tell a user edit, a sync arrival and its own write apart | **Fails (as event types); works by content** | An external write (`adapter.write`) and `processFrontMatter` produce identical `vault.modify` then `metadataCache.changed` events with no source. A move produces only `rename` (no `modify`). Design D-08: an own-write ledger (path plus content hash of what we wrote) identifies our own writes; fingerprints of "content without `modified` and `breadcrumb`" identify moves-with-breadcrumb-rewrites; a sync arrival is a non-own change, which the spec treats the same as an edit for `modified`. |
| U8 | The breadcrumb plugin writes only `breadcrumb`, starting with the root folder | **Untested** | Plugin not installed here. Contract assumed per spec; the plugin only reads. Every weird value is a warning (rule 3). Tested with simulated writes. |

## Spec versus real behaviour: items to report

1. **U6 / rule 9**: `processFrontMatter` does not keep line endings. Resolved by D-07 (own writer); no spec change needed.
2. **Rule 1 / settings "Only notes created or moved on this device can trigger that prompt"**: Obsidian gives no way to tell a locally created note from one that arrived through sync (U7). Resolved by a heuristic, D-08, which can still prompt for a foreign note that arrives with no `id` shortly after creation. Reported rather than hidden.
3. **Schema folder write list**: the spec lets the plugin write only `folders.yaml` and `scope.yaml`, but "installable in a clean vault" needs the starter pack placed in the vault. D-05 adds one explicit, user-triggered "Install starter schema pack" command that never overwrites.
